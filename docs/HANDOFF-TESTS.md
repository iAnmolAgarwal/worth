# Hand-off security checklist: where each line is tested

The store ↔ Worth hand-off contract ends with a security checklist (§7). This table maps each line
to the tests that hold it. Unit and API tests run in `npm test` (and so in `npm run check`). The
real-browser E2E across both origins runs with `npm run test:e2e`, at 1440 and 390 px, and in the
CI job **Two-origin E2E**.

| §7 line | Unit and API tests | Browser E2E (`tests/e2e/handoff.spec.ts`) |
|---|---|---|
| HMAC with direction labels; constant-time compare of canonical signature strings; key ≥ 32 bytes; production refuses partial or invalid config, and runs with the hand-off off when it is wholly unset | `handoff.test.ts`: signs over the direction label; rejects a quote replayed as a result; one spelling of a signature; constant time; base64url secret of 32+ bytes. `config.test.ts`: refuses a partial or invalid configuration in production; starts production with the hand-off off. `merchant/config.test.ts`: refuses production without a 32-byte key | Forged signature and another key: "couldn't verify". Hand-off off: `/check` can't verify any link |
| Anti-forwarding: the store reports only orders whose session got a verified result for that qid; Worth records only with consent and `returnedAt` | `merchant/app.test.ts` › anti-forwarding (3 tests). `report-back.test.ts` › consent, returnedAt and anti-forwarding. `handoff-api.test.ts`: records returnedAt only when it signs a result | A forwarded link credits only the shopper who analysed it and came back |
| An edited price never yields a signed result token | `handoff-api.test.ts`: never signs a verdict once the shopper changed the price. `check-ui.test.tsx`: an edit is a user-claimed price for the decision and the way back | An edited price goes back with no Worth line, by a plain link |
| Origin allowlist for returnUrl and imageUrl; https in production | `handoff.test.ts`: accepts returnUrl and imageUrl only on MERCHANT_ORIGIN. `config.test.ts` and `merchant/config.test.ts`: production refuses http and local origins. `handoff-contract.test.ts`: the production store links to Worth over https with an https way back | Expired quote: the way back is the store's own page |
| Expiry ≤ 15 min; 60 s skew; outcome timestamp ±300 s | `handoff.test.ts`: at most 900 s; expires after exp plus 60 s; iat not more than 60 s ahead; outcome skew over 300 s. `merchant/app.test.ts`: a quote is not valid 15 minutes and a minute later. `report-back.test.ts`: missing, malformed or skewed timestamp | An expired quote says so and offers the plain way back |
| Strict zod schemas; size caps (token 4 KB, outcome 2 KB); names capped and stripped of control characters | `handoff.test.ts`: strict schema; malformed and oversize tokens; hidden characters stripped. `handoff-api.test.ts`: a body over 8 KB. `report-back.test.ts`: a body over 2 KB; shape checked strictly. `check-ui.test.tsx`: never sends a token over 4 KB | A tampered price can't be verified |
| Token in the fragment, removed on read; `Referrer-Policy: no-referrer` on `/check` | `check-ui.test.tsx`: takes `#q=` once and removes it, before verifying. `handoff-api.test.ts`: no referrer from `/check`. `handoff-contract.test.ts`: production `/check` headers | Main flow: the address bar loses the token; it reaches Worth only in the `/api/handoff/open` body, never in a URL or a Referer |
| Report-back idempotent on captureId, recorded only with consent (unticked by default), bound to the session that opened the quote | `report-back.test.ts`: idempotent on captureId; one purchase per quote; consent matrix. `handoff-api.test.ts`: consent starts unticked; a quote binds to its first session. `report-back-e2e.test.ts`: capture path and webhook race | Main flow: consent unticked, one row. A repeated report (store webhook, resent twice, a second capture) stays one row |
| Store-side text reaches Claude only as quoted data; no page text at all | `handoff-contract.test.ts`: the item name reaches Claude once, JSON-quoted and cleaned; the merchant name, links and token never do; Worth fetches nothing | — |
| Worth never calls PayPal for a store's order; the store never trusts the `worth` token for money | `handoff-contract.test.ts`: a whole hand-off and report-back makes no PayPal or outbound call from Worth; the store orders at its catalog price whatever result came back. `handoff-api.test.ts`: the store's Pay in 4 answer, without asking PayPal. `merchant/app.test.ts`: never takes a price from the browser | Main flow: the store's fake PayPal takes the order; Worth only records the report |
| Rate limits: `/open` and `/consent` per IP; `/outcome` signature first, then per mid | `handoff-api.test.ts`: limits hand-off calls per client IP (open, then consent). `report-back.test.ts`: limits each merchant after the signature check | — |
| Unverified-link errors never show a return link | `handoff-api.test.ts`: refuses each bad token with no way back. `check-ui.test.tsx`: unverified link, empty composer, no way back; rate limit shows no way back before verification | Tampered, forged and other-key tokens: no "Back to" link and no link to the store at all |

Every browser test also fails on any `window.open` call (the flow is same-tab, so there is no
popup to block) and on any Content-Security-Policy violation on either origin. Session cookies
are checked in the browser (HttpOnly, SameSite=Lax, one per origin) and, for production's
`__Host-` names and `Secure`, in `handoff-contract.test.ts`, since the E2E runs over plain http.
